# Controlled repair contract v1 (synthetic integration only)

This is artifact verification and data validation, not user authentication or an
executor. Telemetry v1, collection identities, ingestion, foreground scheduling,
and the read-only dashboard stay unchanged. No production signing keys, approved
production manifests, privileged credentials, host commands or repair adapters ship.

Foundation owns `repair_contract.py`, `repair_catalog.py`, this document and its
unique tests. Runtime owns `repair_runtime.py`, `repair_audit.py` and unique tests.
Presentation owns `repair_view.py` and composed tests. Consumers must validate at
public boundaries, not trust class labels. Dataclass construction establishes shape
only. A caller can construct a `VerifiedRunbook` with an invalid signature; only
catalog re-verification establishes artifact trust. Trusted in-process Python code
can replace methods/private state; this library is not a sandbox against its owner.

## Artifact API and wire schema

```python
from gargoyl.repair_catalog import RunbookCatalog, VerifiedRunbook, SIGNING_CONTEXT
from gargoyl.repair_contract import (
    RepairPlan, RepairConfirmation, RepairReceipt, RepairAuditEntry,
    OperationResult, canonical, manifest_bytes, validate_confirmation,
)
catalog = RunbookCatalog(trusted_keys=keys, allowed_versions=pins)
book = catalog.verify_runbook(payload, signature, key_id="test-key")
book = catalog.validate_runbook(book)
plan = catalog.plan(book, target_host, evidence, now=utc)
plan = catalog.validate_plan(plan, now=utc)
confirmation = validate_confirmation(confirmation, plan, now=utc)
```

`keys` is a dict of 1..16 key IDs to raw 32-byte Ed25519 public keys. Key IDs match
`[a-z0-9][a-z0-9_-]{0,63}`. `pins` is a frozenset of 1..64 exact triples
`(runbook_id, version, sha256_hex_of_canonical_manifest)`. Both are copied. Trust
replacement/revocation requires a new catalog; no network discovery or enrollment.
Signature is exactly 64 bytes over `SIGNING_CONTEXT + manifest_bytes(manifest)`;
context is `b"gargoyl:repair:manifest:v1\x00"`. Artifact digest excludes signature.

Manifest is exactly:

```json
{"schema_version":1,"runbook_id":"status_refresh","version":1,
 "operation":"status_refresh","timeout_seconds":5}
```

Operation must equal runbook_id. The five identifiers are `status_refresh`,
`diagnostics_capture`, `drained_provider_restart`, `model_load_retry`, and
`stale_state_reconciliation`. Version is an integer 1..2147483647; timeout an integer
1..30 seconds inclusive, excluding booleans. No command/argument/path/URL/plugin
fields. No retry count, model selection or impact override. A signature cannot
relax these checks or grant user/host authority. Signing uses ephemeral keys in tests
only; deployment trust and actual operation semantics remain separate work.

All wire objects are strict UTF-8 JSON <=65536 bytes, including whitespace on input.
Reject duplicates, nonfinite numbers, unknown fields, malformed types and excessive
nesting with safe `PolicyError`, without input echo. Canonical bytes use sorted keys,
compact separators, `ensure_ascii=True`, no NaN. Every enclosing object has the same
65536-byte total cap, so a plan close to that cap may not fit a receipt/claim; runtime
must construct and size-check its complete claim **before** invoking an operation.
All IDs for actor/click/host are opaque canonical UUIDs, never labels or customer IDs.
All digests are lowercase 64-character hex. Times use existing telemetry UTC grammar.

Each immutable data wrapper takes **one `payload: bytes` argument**, canonicalizes
it, and exposes `.payload` and `.as_dict()` (new detached copy each call).
`VerifiedRunbook.digest` is its manifest digest. `RepairPlan.digest` hashes its entire
canonical payload. None of these objects are credentials.

VerifiedRunbook payload: exactly `manifest` (above), `key_id`, `signature` (128 hex
characters). Its public class name does not certify the payload.

RepairPlan payload: exactly `schema_version:1`, `target_host`, `runbook` (proof
object), `evidence` (list of 0..16 validated complete telemetry snapshots for this
host), `evaluated_at`, `expires_at`, `checks`, `blocked` (bool). Expiry generated by
catalog is evaluation +60 seconds. Evidence is exact-deduplicated and sorted by
canonical bytes; contradictions survive. Each check has exactly `check_id`, `state`
(`passed|blocked|unknown`), `required` (bool). Allowed check IDs:
`artifact_verified`, `evidence_fresh`, `in_flight_work`, `drain_acknowledgement`,
`selected_model`, `model_memory_requirement`, `reconciliation_scope`.

Catalog always produces required artifact_verified/passed. evidence_fresh is passed
only for nonempty evidence with all fields currently observed, no future collection
time and no contradictory same-metric/source/observation-time records; otherwise
unknown. It is informational for status_refresh/diagnostics_capture. Those two
have blocked=False (still require independent authenticated confirmation and an
explicit available adapter). The other three have blocked=True regardless of supplied
telemetry: restart lacks in-flight/drain evidence, model retry lacks in-flight,
selected-model and memory-requirement evidence, reconciliation lacks approved scope.
Their missing checks are required/blocked. No cumulative request count is treated as
in-flight work. No inferred model size/headroom threshold. No busy-work override.

`catalog.validate_plan` re-verifies signature/pins, time window, and recomputes the
entire plan from its evidence; forged checks/blocked/expiry are rejected. Execution
must separately obtain current evidence and compare a newly evaluated safety-relevant
preflight before invocation. Historical audit lookup validates shape/authentication,
not current expiry or current catalog membership (revocation must not erase history).

RepairConfirmation payload: exactly `schema_version:1`, `actor_id`, `click_id`,
`target_host`, `runbook_id`, `version`, `runbook_digest`, `plan_digest`, `confirmed_at`,
`expires_at`, `impact_acknowledged:false`. Validity is >0..60 seconds; binding validator
requires plan evaluation <= confirmation <= now < confirmation expiry <= plan expiry,
and exact host/runbook/version/digests. **This validates intent data, not identity or
an actual click.** A separately supplied trusted user-authorization boundary must
validate authority for that actor, host and operation. Never accept a collector
identity or a caller-supplied boolean as that proof.

RepairReceipt payload: exactly `schema_version:1`, `actor_id`, `click_id`,
`target_host`, `runbook_id`, `version`, `runbook_digest`, `plan_digest`, `preflight`
(full plan), `started_at`, `finished_at`, `stage`, `outcome`, `reason`,
`cleanup_complete` (bool). Plan/digests/host/version must bind; finished>=started.
Success requires stage=completion, reason=completed, cleanup_complete=True and an
unblocked preflight. Incomplete cleanup requires outcome_unknown. A receipt is data,
not proof it was durably stored or returned by an authorized executor.

Enums exported from repair_contract:

- STAGES: preflight, claim, execution, completion.
- OUTCOMES: succeeded, blocked, failed, cancelled, outcome_unknown.
- REASONS: completed, preconditions_blocked, authorization_denied,
  confirmation_expired, plan_changed, catalog_rejected, already_claimed,
  audit_unavailable, operation_unavailable, operation_failed, deadline_exceeded,
  cancelled, cleanup_incomplete, interrupted, invalid_result, recovery_required,
  clock_invalid.

### Shared outcome compatibility (validation, not authorization)

`validate_outcome(outcome, reason, cleanup_complete, *, stage)` is shared by
OperationResult.validate, RepairReceipt, and transitively finished RepairAuditEntry.
The schemas and enums are unchanged; these combinations are now enforced:

| Reason | Outcome | Stage | Cleanup |
| --- | --- | --- | --- |
| completed | succeeded | completion | true |
| preconditions_blocked, authorization_denied, confirmation_expired, plan_changed, catalog_rejected, already_claimed, operation_unavailable | blocked | preflight or claim | true |
| operation_failed | failed | execution or completion | true |
| cancelled | cancelled or outcome_unknown | any | cancelled requires true; unknown permits either |
| audit_unavailable | blocked | preflight or claim | true |
| audit_unavailable | outcome_unknown | claim, execution or completion | either |
| deadline_exceeded, invalid_result | outcome_unknown | execution or completion | either |
| cleanup_incomplete | outcome_unknown | execution or completion | false |
| recovery_required | outcome_unknown | claim or completion | either |
| clock_invalid, interrupted | outcome_unknown | any | either |

No other combination is accepted. Adapter results are validated with stage=completion
(the call returned) and cannot use blocked. Runtime receipts must use their actual
stage. A timeout, interruption or invalid result cannot establish definite failure;
clean process cleanup alone cannot establish whether a side effect occurred.
Cancellation is definite only when the adapter can establish its outcome; otherwise
return outcome_unknown/cancelled. Before invocation, refuse as blocked at preflight
or claim; after invocation an audit failure must be outcome_unknown. A known safe
pre-invocation cancellation can use cancelled/cancelled; interrupted is conservative
uncertainty. None of these validations verifies an operation actually took place or
that an actor was authorized.

Raw errors/stdout/stderr, prompts/completions, model labels, addresses and credentials
are never fields. Exact outcomes mean honest fixed stage/status/reason and uncertainty,
not a raw exception dump. Backward wall-clock movement after starting must be reported
unknown/clock_invalid; use the last valid timestamp for finished_at and document this
clock limitation rather than asserting a trustworthy finish timestamp.

## Runtime/audit handoff (implemented by the runtime lane)

Suggested fixed API, owned by that lane; report incompatibilities before changes:

```python
RepairAuditStore(directory, *, key: bytes, max_records=1000)
store.claim(plan: RepairPlan, confirmation: RepairConfirmation, *, now: str) -> bool
store.lookup(click_id: str) -> RepairAuditEntry | None
store.finalize(click_id: str, receipt: RepairReceipt) -> RepairAuditEntry
store.close()

adapter.supported_operations: frozenset[str]
adapter.total_timeout_seconds: float  # finite 0 < budget <= manifest timeout <= 30
adapter.execute(plan: RepairPlan, *, stop_event) -> OperationResult
```

`OperationResult(outcome, reason, cleanup_complete)` is a frozen dataclass with
`.validate() -> detached OperationResult`; runtime must call it after checking exact
type. Allowed outcomes exclude blocked (refuse before invoking); enums as above.
The shared compatibility validator below also applies; incomplete cleanup requires outcome_unknown.
Adapter must actually honor a total cleanup-inclusive deadline and return truthful
certainty. A background thread timeout cannot stop arbitrary side effects. No default
production adapter; refusal happens before a durable claim. Fakes/synthetic processes
are explicitly test-only. No automatic retries, rollback, or resume.

RepairAuditEntry payload: exactly `schema_version:1`, `state:started|finished`,
`plan` (full plan), `confirmation` (full confirmation), `started_at`, `receipt`
(null for started, full bound receipt for finished). Constructor validates claim
binding at started_at and terminal attribution. This is a historical validator.

Store claims atomically consume click_id and persist authenticated encrypted started
entry before returning True. Same ID with same canonical plan/confirmation returns
False; different content must raise a safe error. No operation on False. lookup None
means genuinely absent, never corruption/unreadability. Started entry after restart
means outcome_unknown/recovery_required: lookup only, no reset/resume. Finalize commits
bound terminal data; idempotent exact terminal replay allowed, conflicting overwrite
rejected. Finalize failure after invocation leaves original claim consumed and runtime
reports outcome_unknown/audit_unavailable. It must not infer no side effect occurred.

Audit encryption/schema/domain is separate from telemetry `SpoolCipher`; explicitly
supplied 32-byte synthetic key for tests, no key loading/provisioning. Use private local
store with authenticated records and atomic durable commits; no plaintext fallback.
Max records integer 1..10000; fail closed at capacity. **Never evict consumed click IDs**
to admit another repair. No automatic retention prune, reset or migration in this slice.
Corrupt/missing expected store state fails closed; deletion/rollback by a privileged
owner is outside local durability guarantees and must not be advertised as tamper-proof.
Keep storage errors fixed/safe. Single-owner synchronous runtime is sufficient; state
and claim transitions must serialize concurrent calls if the store allows sharing.

repository environment. Foundation tests create temporary signing keys in memory;
no real runbook is signed/installed. Tests verify trust separation, strict schemas,
forged objects/plans, exact allowlists, time/size bounds and privacy rejection.
